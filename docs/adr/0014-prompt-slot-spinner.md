# Prompt-slot spinner replaces the standalone "Working" line

We decided (2026-09, pi 0.85.1) to replace pi's standalone "Working (⛟ …)" status line with a spinner animation on the custom editor's **top border row** (the `┌────┐` row): while the agent is busy, a 4-cell window that moves in it (left-ish, starts 6 dashes in, shifts left on narrow boxes, is skipped when too narrow to fit) **fills cell-by-cell left→right, each cell walking the 8 Unicode braille-chart-order stages in 2-step line pairs (⠁⠉ / ⠋⠛ / ⠟⠿ / ⡿⣿), so the 2×4 braille dot block grows across the window line by line, followed by a ' Working' label while busy (rendered via the `time` palette; omitted, not standalone, when the box is too narrow) (32 = 4×8 steps), holds, clears, repeats**, at 80 ms per tick. Every cell of the window shows its stage char via the `spin` (accent) palette; the empty clear step (the cycle's head tick) is plain spaces — **the border line breaks at the window's columns**. The precomputed frame sequence is deterministic per instance; in EAW terminals (`⣿` reporting visible width 2) the stage table falls back to a width-1 shading set of the same 8 stages (░ → █) following the same cell-wise order. The `>` chevron **stays always static** in the prefix slot, and the plain border row repaints exactly once on the busy→idle transition (the typing strip must NOT freeze on screen — an idle→no-op would). The feature is gated by `archimedes.core.editorSpinBorder` (default **on**; settings item "Editor Spin Border"), and while on we hide the "working" indicator kind via `ctx.ui.setWorkingVisible(false)` on `session_start`, restoring it on `session_shutdown`.

Context: pi 0.85.0 moved the working indicator *into* the default editor's top border. Custom editors keep the old standalone status line unless they opt into `embedWorkingStatus` — but our `HephaestusEditor` fully re-renders its chrome, so the embedded indicator would be silently swallowed by the re-render. The native position was therefore effectively unavailable to us, and the standalone line (with its "Working ⛟ …" text and "esc to interrupt" label) is the only surviving native option. A prompt-slot spinner keeps the busy signal on screen, keeps the terminal quiet, and matches the chrome we already own; the plan file ([`docs/roadmap/prompt-slot-spinner.md`](../roadmap/prompt-slot-spinner.md)) and the 0.85.x changelog review it cites document the review that led here.

The mechanism is a self-driven 80 ms interval owned by the editor and hoisted to module scope in core's extension hooks — not `embedWorkingStatus` plus access to private editor internals. Verified against the 0.85.1 bundle: `setCustomEditorComponent` does **not** `dispose()` the replaced editor, so the shutdown/`/reload` paths explicitly reap the module-scoped timer (`clearSpinInterval()` re-runs on every `session_start`, including a `/reload` rebind); the `dispose()` override is a safety net only. `setWorkingVisible` affects only the "working" kind, so the other indicator lines (retry, compaction, branch summary) continue to render as their own lines. The animation mechanism itself — the stage sets, the precomputed 32-frame cell-by-line fill table, and the busy/idle tick machine — lives in the `BorderTypeSpinner` util in `packages/core/src/editor/spin.ts`; the editor owns the 80 ms timer, the narrow-border guards, and the border-row assembly.

Trade-offs accepted: we lose the "esc to interrupt" label and the "Working (⛟ …)" text while a turn runs (the animation itself is the signal, and esc still works). The retry/compaction/branch-summary indicator lines remain standalone lines rather than being folded into the chrome — they are a different indicator kind from "working" and `setWorkingVisible` does not reach them.

Reversal path: no hot-swap — toggle "Editor Spin Prompt" **Off** (or `archimedes.core.editorSpinPrompt: false`) and start the next session (a `/reload` also re-applies it). The off path is fully inert — no timer, no hide call, unconditional `setWorkingVisible(true)` on session start — so pi's default "Working" line returns.

Consequences:
- Core's `session_start` loads config before registering the editor factory (the `loadCoreConfig` call moved up), hides the "working" kind conditionally (`setWorkingVisible(!spinFlag)` — the unconditional form double-recovers a carried-over hidden state even when off), and passes the timer handle up via `onSpinInterval`; `session_shutdown` restores visibility (enabled only), reaps the timer, and resets the flag so a second shutdown is a no-op. The editor never imports the extension index (no circular import) — the callback keeps the gap one-way.
- The editor's `dispose()` override is declared **without `override`** (verified: no pi-tui base class declares `dispose()` at 0.85.1) — do not "fix" it.
- Speed and label are user-configurable (`archimedes.core.editorSpinSpeed` — since the style selector switched `editorSpinSpeed` to the gallery-native speed multipliers: slow/normal/fast = × 1.5 / × 1 / × 0.6 of the style's native per-tick interval, typing: 120 / 80 / 48 ms; `editorSpinLabel`, empty hides the label), under a 32 ms tick floor that also caps a 30 ms native style at 32 under `fast`.
- A style selector (`archimedes.core.editorSpinStyle`, ten gallery-derived styles, default **typing**; an unknown or not-yet-ported value normalizes to typing via `BorderTypeSpinner`'s `normalizeSpinnerStyle` fallback) and per-style native tempo × speed multiplier, 32 ms tick floor. *(Note: `typing` ships; the other nine port styles land in batches 2–4 and this ADR is revised when they do.)*
- The window's stage set is chosen once per instance via `visibleWidth("⣿") === 1`; in EAW terminals (where `⣿` has visible width 2) the stage table falls back to the width-1 shading set (░ → █), so the 4-cell window stays width 1 per cell and the autocomplete indent (`PI_SYMBOL_COL = 2`) is preserved — the shading walks the same cell-wise line-pair order as the braille set.
- All reached window cells render via a dedicated `spin` palette entry (`accent` → `borderMuted` fallback), so the animation can be recolored independently of the static `>` (the `prefix` palette entry, `borderMuted` → `border`); not-yet-reached cells and the empty clear step's cells are plain spaces (`U+0020`, unstyled) — no `frame` color, no extra reset — so the border line breaks at the window's columns.

Manual verification checklist:
- [ ] Start a turn — the 4-cell window **fills cell-by-cell left→right, each cell walking the 8 chart-order stages in 2-step line pairs (⠁⠉ / ⠋⠛ / ⠟⠿ / ⡿⣿), so the 2×4 braille dot block grows across the window line by line, followed by a ' Working' label while busy (32 steps) on the `┌──┐` top border row** (left-ish, 6 dashes in), the empty clear step breaks the border line (spaces), the static `>` prefix stays static, the standalone "Working (⛟ …)" line is gone.
- [ ] Turn ends — the plain all-dash `─` border row and static `>` return within one tick (~80 ms); no leftover stage chars or spaces in the window positions.
- [ ] `/compact` mid-run — the compaction indicator line shows **and** the spinner keeps animating.
- [ ] Toggle "Editor Spin Border" Off + `/reload` — pi's default "Working" line is back; no orphaned timer (devtools: no leaked interval).
- [ ] Narrow terminal — the 4-cell window shifts left and stays aligned; very narrow (below `CELLS + 4` inner columns) → plain border, no window.
- [ ] East-Asian-width terminal — `⣿` reports visible width 2 → the stage set falls back to the width-1 shading (░ → █, no font-sinking, no EAW push-out), walking the same cell-wise order, 4-cell window intact, autocomplete line aligned under the prefix.
